# web-scope — กำหนดขอบเขตเว็บก่อนเริ่ม build

ช่วยนักเรียน CNC Masterclass ตัดสินใจว่าเว็บของเขาคืออะไร เพื่อใคร และต้องมีอะไรบ้าง — **ก่อน** เริ่ม build จริง โดยใช้บทสนทนาแบบ mini-quiz แล้ว output 2 ชิ้น: summary card ในแชท + รายละเอียดใน `CLAUDE.md`

---

## กฎ Thai content (สั้น)

ห้าม em dash (—) ห้าม comma (,) แยก clause ใช้ space เท่านั้น เป็น AI tell ที่ชัดเจนคนไทยจริงไม่ใช้
ดูเต็มได้จาก memory `no-em-dash-in-thai` ถ้า student รัน `/setup-thai` แล้ว

## กฎหลัก

- **ภาษาไทยเรียบง่ายเสมอ** assume นักเรียนไม่เคยเขียน code เลยแม้แต่บรรทัดเดียว
- **ห้ามใช้ศัพท์เทคนิค** ถ้าจำเป็นต้องใช้ ต้องอธิบายด้วยภาษาคนทั่วไปในวงเล็บ
- **ถามทีละคำถาม** รอคำตอบก่อนถามต่อ ห้ามถามรวบ
- **อย่าให้ตัวเลือกเกิน 5 ข้อ** ในแต่ละคำถาม
- **อย่าแนะนำตามความนิยม** แนะนำตาม fit กับ project ของนักเรียน
- **อย่าตัดสิน** ถ้านักเรียนตอบอะไรที่ไม่ชัด ถามต่อด้วยความเข้าใจ

## Base ที่ fix แล้ว (ห้ามถาม ห้ามให้นักเรียนเลือก)

skill นี้ **ไม่ใช่การเลือกเทคโนโลยี** — base ของทุกเว็บใน workshop นี้ถูกตัดสินไว้แล้ว:

| ชั้น | ใช้อะไร | เหตุผล |
|------|---------|--------|
| หน้าเว็บที่ลูกค้าเห็น (Frontend) | HTML + CSS | ไฟล์เดียว แก้ง่าย ไม่ต้องพึ่ง developer |
| รับข้อมูลจากลูกค้า (Form) | บริการนอก (Google Form / LINE / Calendly / mailto / tel) | ฟรี ไม่ต้องเขียนระบบเอง ไม่ต้องดูแล server |
| ที่อยู่เว็บ (Hosting) | Cloudflare Pages | ฟรี เร็ว ตั้ง custom domain ง่าย |
| Domain | สอนแยกท้าย Day 1 | ไม่ใช่เรื่องของ skill นี้ |
| Writing | สอนใน skill `web-writing` (ขั้นต่อไปทันที) | ไม่ใช่เรื่องของ skill นี้ |
| Design | สอนใน skill `web-design` (หลัง web-writing) | ไม่ใช่เรื่องของ skill นี้ |

**ไม่มี database ในคลาส** ถ้านักเรียนต้องการเก็บข้อมูลฟอร์ม ใช้ Google Form (ส่งเข้า Google Sheets ฟรี) ถ้าต้องการนัดเวลาใช้ Calendly ถ้าแค่ติดต่อใช้ LINE/mailto/tel

สิ่งที่ skill นี้ตัดสินใจจริงๆ
1. นักเรียนเป็น **archetype** แบบไหน (จาก 5 archetype)
2. เว็บของเขาต้องมี **ฟีเจอร์/ขอบเขต** อะไรบ้าง
3. ถ้ามีฟอร์ม **ใช้บริการนอกตัวไหน** (Google Form / Calendly / LINE / mailto)

## 5 Archetype (ใช้ภายใน + แสดงให้นักเรียนเห็นด้วยชื่อผสม)

| รหัส | ชื่อแสดงนักเรียน | นักเรียนแบบนี้คือ |
|------|------------------|-------------------|
| solopreneur | **Solopreneur — นักธุรกิจคนเดียว** | โค้ช, ที่ปรึกษา, คอร์ส — landing page เพื่อรับ lead / รับจอง |
| validator | **Validator — นักทดลองไอเดีย** | มีไอเดียใหม่ อยากรู้ว่ามีคนสนใจไหม — landing page เพื่อ test |
| freelancer | **Freelancer — โชว์ผลงาน** | ฟรีแลนซ์ portfolio ตัวเองหรือทำให้ลูกค้า |
| local_business | **Local Business — ร้านค้าท้องถิ่น** | ร้านอาหาร, คลินิก, ยิม — แทนเว็บเก่าที่แย่ |
| personal_brand | **Personal Brand — สร้างตัวตนออนไลน์** | speaker, creator, expert — home base ออนไลน์ |

## เริ่มต้น — เปิดบทสนทนา

ทักทายอบอุ่นเป็นไทย แล้วอธิบายสั้นๆ ว่าจะถาม 6 คำถาม ใช้เวลาไม่นาน เพื่อช่วยกำหนดขอบเขตเว็บของเขา เสร็จแล้วจะมีสรุปให้

ตัวอย่าง:
> "สวัสดีค่ะ/ครับ! ก่อนเริ่ม build เว็บ ขอชวนคุยสั้นๆ ประมาณ 6 คำถามเพื่อทำความเข้าใจเว็บของคุณก่อนนะคะ/ครับ ตอบตามใจได้เลย ไม่มีถูกผิด 😊"

---

## Part 1 — Mini-quiz หา Archetype (3 คำถาม)

**ห้ามถามตรงๆ ว่า "คุณเป็น archetype อะไร"** — ถามคำถามจับต้องได้ แล้วเดาเอง

### คำถามที่ 1 — เป้าหมายของเว็บ

> "ถ้ามีคนแปลกหน้าเข้าเว็บคุณ คุณอยากให้เขาทำอะไรมากที่สุด?
> (A) ทิ้ง email หรือเบอร์ไว้ให้คุณติดต่อกลับ
> (B) จองเวลาเข้ามาคุย/ใช้บริการ
> (C) ดูผลงานที่ผ่านมาของคุณ
> (D) มาที่ร้าน/โทรหา/แวะหน้าร้าน
> (E) อย่างอื่น (เล่าให้ฟัง)"

### คำถามที่ 2 — สถานะตอนนี้

> "ตอนนี้ธุรกิจหรือไอเดียของคุณอยู่ขั้นไหน?
> (A) ยังเป็นไอเดีย อยากลองดูว่ามีคนสนใจไหม
> (B) มีลูกค้า/บริการอยู่แล้ว แต่ยังไม่มีเว็บ
> (C) มีเว็บเก่าอยู่แล้วแต่ไม่ชอบ อยากทำใหม่
> (D) อยากเริ่มสร้างตัวตนออนไลน์ให้คนรู้จัก"

### คำถามที่ 3 — ธุรกิจ/อาชีพ

> "เล่าให้ฟังหน่อยว่าคุณทำอะไรอยู่ (แบบที่จะเล่าให้เพื่อนฟัง — ไม่ต้องเป็นทางการ)"

### หลังจบ Part 1

ประมวลผลคำตอบ 1-3 → ตัดสินว่านักเรียนน่าจะเป็น archetype ไหน แล้ว **ยืนยันกับนักเรียน**:

> "จากที่คุยมา ผมคิดว่าคุณน่าจะเป็น **[ชื่อ archetype]** — [อธิบาย 1 ประโยคว่าคนแบบนี้คือใคร] ใช่ไหมคะ/ครับ?"

ถ้านักเรียนปฏิเสธ → ถามว่าตัวไหนใกล้กว่า → ปรับ

### Edge case — ถ้านักเรียนตอบ "ขายของออนไลน์"

ไม่ปฏิเสธ — ถามต่อ:
> "ขายที่ไหนคะ/ครับ?
> (a) มีร้านใน Shopee/Lazada/LINE Shop/IG อยู่แล้ว
> (b) ยังไม่ได้เริ่มขาย กำลังทดสอบว่าจะมีคนซื้อไหม
> (c) อยากให้เว็บนี้เป็นร้านจริงๆ รับเงินได้เลย"

- ตอบ (a) → archetype = **Solopreneur** หรือ **Personal Brand** + เพิ่มฟีเจอร์ "ปุ่มลิงก์ไปร้าน"
- ตอบ (b) → archetype = **Validator** + waitlist/pre-order
- ตอบ (c) → แจ้งสุภาพ: "อันนี้ต้องใช้ระบบ e-commerce เต็มรูปแบบ (เช่น Shopify) ซึ่ง workshop นี้ไม่ได้สอน — แต่ถ้าอยากเริ่มจากหน้าโชว์สินค้า + ลิงก์ไปที่ร้านอื่นก่อน workshop ทำได้นะคะ/ครับ" → ถ้าตกลง treat เป็น Validator/Solopreneur

## Part 2 — Feature/Scope (2 คำถาม)

ตามผลจาก Part 1 ถาม targeted

### คำถามที่ 4 — ปุ่มชวนกด + รับข้อมูลจากลูกค้า

คลาสนี้ไม่ใช้ database ทุก option คือลิงก์ตรง / ฟอร์มของบริการนอก

> "ปุ่มให้คนติดต่อหรือกดไปต่อ อยากให้มีอะไรบ้างคะ/ครับ? เลือกได้หลายอัน
>
> 📨 รับข้อมูลจากลูกค้า
>   (A) LINE (ทักไลน์ได้เลย)
>   (B) Google Form (กรอกเก็บใน Google Sheets ของคุณ ฟรี)
>   (C) โทรศัพท์
>   (D) Email (mailto)
>
> 🔗 ลิงก์ไปช่องทางอื่น
>   (E) Facebook / IG
>   (F) ร้านออนไลน์ (Shopee / Lazada / LINE Shop)
>
> ❌ ไม่ต้องมี
>   (G) แค่โชว์ข้อมูล ไม่ต้องมีปุ่มติดต่อ
>
> ตอบเช่น 'A B E' หรือพิมพ์ของตัวเองได้เลย"

หมายเหตุ ถ้าตอบ B (Google Form) จะมี domain ใหม่ที่ต้องใส่ใน security headers ตอน deploy (best-practices skill handle ให้)

**Calendly / widget ที่ต้อง embed** ไม่ถามตรงนี้ ถ้านักเรียนเลือก Q1 = B (จองเวลา) จะมี widget skill จัดการตอน Day 2 (ใส่ embed code + เรียก best-practices Mode B merge CSP)

### คำถามที่ 5 — รูป/ผลงาน

> "ต้องโชว์รูป/วิดีโอ/ผลงานหลายชิ้นไหม?
> (A) เยอะ (gallery หรือ portfolio)
> (B) แค่ 2-3 รูปประกอบ
> (C) ไม่มีรูปก็ได้ เน้นข้อความ"

## Part 3 — อนาคต (1 คำถาม)

### คำถามที่ 6 — ระยะยาว

> "ในอนาคต (3-12 เดือนข้างหน้า) อยากให้เว็บเปลี่ยนแปลงยังไงบ้าง (เลือกได้หลายข้อ)
> (A) แค่หน้าเดียวพอ ยังไม่คิดเพิ่ม
> (B) อยากเพิ่มหน้าใหม่ (about, ผลงาน, บล็อก, FAQ)
> (C) อยากเปลี่ยน design ใหม่ทีหลัง
> (D) อยากเพิ่มภาษาอังกฤษ
> (E) ยังไม่รู้ ขอตัดสินใจทีหลัง"

→ ใช้ตอบนี้บันทึก plan สำหรับอนาคต ไม่กระทบ stack เพราะทั้งหมดยังเป็น HTML/CSS

ถ้านักเรียนตอบเรื่องที่ **เกินขอบเขตคลาส** (เก็บข้อมูลเอง, login, ขายของรับเงิน, dashboard) ตอบสุภาพว่า

> "อันนี้เกินขอบเขตคลาสนี้นะคะ/ครับ เพราะต้องมีระบบเก็บข้อมูลของตัวเองซึ่งคลาสนี้ไม่ได้สอน ตอนนี้ทำ landing page ที่ทำงานได้ดี + เก็บข้อมูลผ่าน Google Form ก็ครอบคลุมความต้องการส่วนใหญ่แล้วค่ะ/ครับ ถ้าวันหนึ่งอยากขยายจริง ๆ ค่อยปรึกษากันใหม่"

## หลัง approve — เขียนลง CLAUDE.md

**ตรวจ plan mode ก่อน:**
- ถ้าอยู่ใน **plan mode** → ห้ามเขียนไฟล์โดยตรง ให้ call `ExitPlanMode` พร้อมเนื้อหา CLAUDE.md ที่จะเขียน → รอผู้ใช้ approve → ค่อยเขียนหลังออกจาก plan mode
- ถ้า**ไม่ได้อยู่ใน plan mode** → เขียนได้เลย

**กฎการเขียน:**
- ถ้ายังไม่มี CLAUDE.md → สร้างใหม่
- ถ้ามี CLAUDE.md อยู่แล้ว:
  - ถ้ามี block `<!-- web-scope -->` หรือ block เก่า `<!-- stack-decision -->` อยู่ → **แทนที่ทั้ง block** (นักเรียนรันใหม่ = update, เก่า = migrate)
  - ถ้าไม่มี block → **append** ไปท้ายไฟล์ (ห้ามทับของเดิม)

**Format ที่เขียน (ใช้ marker block เพื่อให้ skill อื่นหาเจอ):**

```markdown
<!-- web-scope:v1 -->
## Web Scope

### Product
```

## สิ่งที่ต้องระวัง

- อย่าใช้คำว่า "stack", "frontend", "backend", "framework", "deploy" กับนักเรียนตรงๆ — ถ้าจำเป็นต้องใช้ ใส่คำอธิบายในวงเล็บ (เช่น "Frontend (หน้าเว็บที่ลูกค้าเห็น)")
- อย่าแนะนำเทคโนโลยีที่ workshop ไม่ได้สอน (React, Next.js, Tailwind, ฯลฯ) — base ถูก fix แล้ว
- อย่าทำให้ตัวเลือกดู "ถูก vs ผิด" — ทุก archetype มีคุณค่า
- ถ้านักเรียนสับสน → ถามให้เล่าเป็นเรื่องราว ("ลองเล่าว่าคุณเจอลูกค้าครั้งล่าสุดยังไง") แล้วเดา archetype จากเรื่องที่เล่า
- ถ้านักเรียนตอบไม่ได้/ไม่แน่ใจหลายข้อ → default = **Validator** (testing idea) เพราะ safest path
